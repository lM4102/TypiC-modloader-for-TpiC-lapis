First steps

WARNING: This is version 1.0.0, but it could easily be 0.1.0, so many things are missing (because I forgot to add them). Custom scripts (or sprites) are experimental and can have more bugs than the rest of the modloader. Everything can have a lot of bugs; making a modloader is hard, and I started this one a month or two ago. After throwing this 398-character line at you, I'll let you learn how to mod on TypiC.

First of all, you have two ways of modding: using blocks in Turbowarp (A mod of Scratch) or manually writing JSON files and binary sprite3 files. This guide will cover the easiest way (Coding in Turbowarp).

If you don't know what Turbowarp is, it is a mod of Scratch that makes projects run faster and lets people make custom extensions in JavaScript. You can download Turbowarp desktop or use the online version.

This guide requires a little knowledge of how to code in Turbowarp


To start modding, first download the three files needed to start modding from the Main page. Once you have downloaded them, open Turbowarp and delete all the sprites (Except the stage).

Adding the TpiC extension

Click the add extension button at the bottom-left corner and then search for Custom Extension and click it. Go to the "Files" option and select the TpiC Modloader extension.js file. Also check the box that says "Run without sandbox", unless you don't want to code a mod.

Adding the Compiler

Click the Upload sprite button (Shown below) and then select the Compiler.sprite3 file

You don't have to do anything with the compiler. Leave it there. Let it be alone. The blocks of the compiler aren't shown in the palette, so if you delete one, you will have to add the compiler again

The Mod Sprite

Sadly, the compiler won't run when you speak to your computer saying "Compiler, start the game". Draw a new empty sprite and set its name to whatever you want, but I recommend you to set it to Mod Sprite or something like that. Starting The Game

It MAY look simple, but it's REALLY simple. You just have to make the blocks in the Mod Sprite start running (For example, in the image above, click the green flag) and then, if it's the first time running since you opened Turbowarp, it will ask you to select the game file. Select the TpiC Lapis TypiC Mod developer version file. It has some tweaks to work with the compiler and it has a debug sprite (Explained later). Also, if you want to set the game file manually, the block is on the palette and is called "Setup game"

Making the assets

Images are vector costumes. If it is not a vector costume, it won't work. There are online tools to convert from PNG to SVG (Scalable Vector Graphics) and Turbowarp lets you draw the costumes. For you to have an idea of the sizes, Skill-Drop is 100x197, but then is scaled down to its 55% size, so it's 55x108

It's also important to know that Skill-Drop only takes damage when it touches red (#ff0000 or 255,0,0).

Setting everything

Here is a list of the parameters and what they do:

  • If it has to load the danger image. The danger image is an image only used for organization purposes. I don't recommend you to use it. But it's there if you want.

  • The name of the map. In our example of a lava world, it's going to be Lava land.

  • The map. The costume you select will be the map. What is shown in the screen and the hitbox of your map.

  • Costume that is the danger image. If you selected false in "shall load danger image?" then you can put this to whatever you want, is not going to load.

  • The music for the map. Unfortunately, I was too lazy to make it loop, so I recommend you to make it very long, maybe copying and pasting it 500000000 times

  • Costume to use for the background. Simple, right?

  • Where does the teleporter live. The menu updates when you run the game to add your custom maps.

  • Coordinates of the teleporter. Use the Position Getter Tool to get the positions. It's not precise and it doesn't have all the locations but you can use it and it's going to help.

  • If the teleporter uses a custom image or uses the image by default (A door with the number 4 on it.)

  • If you selected "true" in the last parameter, this costume will be the image displayed for the teleporter.

  • The last parameter. I thought this was infinite. The destination x and y of the teleporter. The Position Getter Tool can help here too

Now that you have set the parameters, you can start the game and see if it works. Also, you may spend some time adjusting the positions of the teleporter

Placeholders

It's VERY IMPORTANT that you use the event placeholders. You have to use them so your code doesn't run in the wrong place. And if still you think you can use the normal events, the green flag placeholder doesn't fire when the green flag is clicked, it is fired when the sprite is created. When compiled, they are transformed into their normal versions. They are on the Event placeholders section of the palette

The "When backdrop switches to" placeholder event doesn't work. It doesn't transform into its original version. It's only there to fill the space.

The variable placeholder blocks have their real usage even when used outside the custom sprite, so they're good for testing. (The real usage only works when the game is running)

There are three placeholder menus: The Sprites Menu and the Variables Menu and the Broadcast Messages Menu

The variables menu

It's the placeholder version of the rounded variable blocks. It still gives you the variable value when you click it and the game is running.

Use it like the normal rounded variable blocks.

The broadcast message menu

Put it in the "broadcast" and "broadcast and wait" blocks as the message, and that's it. It won't work like its original version.

The sprites menu

Put it in every space for selecting a sprite to select a sprite from the game. It will not work like its original version.

Other blocks

Every variable or message you create and that is used in the sprite will be added in the game, but the blocks that change that variable can't be used.

You may notice you can't do anything with lists. You didn't expect me to add all the blocks that interact with lists in the first version, right? But you can still access the game lists if you create a list with EXACTLY the same name and use it as if it were the real list. That's what's called a Shadow Field in SpongePowered Mixins.

Debug controls

The mod developer version adds a debug sprite with some useful utilities:

  • If you press 1, it will add 1 drop to your drops collected
  • If you press 2, you will enter into freecam mode: Skill-Drop will be paused and you will be able to move the camera with WASD
  • If you press c, you will switch between the normal castle and the underground area
